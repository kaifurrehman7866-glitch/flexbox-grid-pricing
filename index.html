Comparison: What Was Easier / Harder

Aspect Flexbox Grid
Setting up 3 equal columns Easy — flex: 1 1 0 on each card does it, but it's really "distribute space evenly," not a true column system. Just as easy, and more explicit — grid-template-columns: repeat(3, 1fr) reads like an actual column definition.
Making the responsive stack One line: flex-direction: column. Very intuitive since Flexbox is already 1-dimensional. Also one line: grid-template-columns: 1fr. Slightly less obvious conceptually (you're collapsing the column tracks, not "changing direction").
Gaps between cards Same — gap works identically in both. Same — gap works identically in both.
Controlling card width precisely Slightly fiddly — needed min-width: 0 to stop long content (like the ul list) from forcing cards wider than their flex-basis. No fiddling needed — Grid tracks strictly respect the 1fr sizing regardless of content, so nothing overflowed.
Header + card row + footer structure Natural — Flexbox is great for stacking a header, a row of cards, and a footer since each is really just a block in normal flow (only the card row itself needed flex). Same result, but felt like slight overkill to reach for Grid just for the card row when the outer header/footer/row structure is really a simple vertical stack.
Overall mental model Thinks in terms of "items in a line that can wrap/shrink/grow" — very natural for a single row of cards. Thinks in terms of "a layout grid with defined tracks" — more setup upfront (defining columns), but scales better if this layout ever needed uneven columns or a 2D structure (e.g. featured card spanning rows).

Takeaway: for a single row of equal-width cards like this pricing section, Flexbox and Grid end up almost identical in code length and difficulty. Flexbox felt slightly more natural since the layout is genuinely one-dimensional (just three items in a row), while Grid's explicit track definitions would start paying off more if the layout became two-dimensional — e.g. adding a comparison table below the cards that needs to align to the same columns.
